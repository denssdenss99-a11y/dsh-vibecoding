# dsh-vibecoding 🎯

[![License: MIT](https://img.shields.io/badge/License-MIT-green.svg)](LICENSE)
[![DSH Plugin](https://img.shields.io/badge/DSH-Plugin-blue.svg)](https://github.com/deepseek-ai/deepseek-harness)

**dsh-vibecoding** — плагин и TDD-оркестратор для [DeepSeek Harness (DSH)](https://github.com/deepseek-ai/deepseek-harness), превращающий обычный хаотичный «вайбкодинг» в строгий, надежный и предсказуемый инженерный процесс с контролем качества и изоляцией веток.

Включает удобную **кнопку переключения режима прямо в панели ввода DSH Web UI**!

---

## 🛑 Проблема «неправильного» вайбкодинга

1. **Промпт без деталей:** модель принимает архитектурные решения вслепую, додумывая бизнес-логику.
2. **Потеря контекста:** на длинных дистанциях диалога модель «забывает» исходную постановку задачи.
3. **Слепая вера в ответ:** фраза модели *«Готово, всё работает»* не означает, что код хотя бы запускается.
4. **Одноагентный режим:** одна дорогая модель делает и сложное планирование, и рутинный кодинг в один поток.

---

## ⚡ 5 Элементов надежного AI-Workflow

1. ❓ **Опрос (Clarification):** Запрет на написание кода до того, как модель задаст 2–4 уточняющих вопроса по граничным условиям и контрактам.
2. 📄 **Спецификация (Anchor):** Автоматическая фиксация плана и контрактов в `docs/specs/<feature>.md`, удерживающая фокус контекста при любых длительных диалогах.
3. 🔴 **TDD-контракт (Red -> Green Loop):** Тесты пишутся **ДО** реализации. Инструмент `run_tdd_cycle` проверяет, что тест сначала упал (RED), затем воркер крутит цикл исправлений сам до тех пор, пока тест не станет зеленым (GREEN).
4. 🌿 **Изолированные ветки (Git Worktrees):** Инструмент `worktree_create` создает изолированную директорию `.worktrees/<task>`, защищая основную ветку от поломок и конфликтов.
5. 🤖 **Оркестрация (Оркестратор + Воркеры):** Сильная модель (Gemini Pro / DeepSeek Reasoner) проектирует и валидирует, а быстрые модели (Gemini Flash / DeepSeek Chat) параллельно пишут код под падающие тесты в своих ветках.

## 🖥️ UI Кнопка в DSH Web

Плагин регистрирует кнопку **`🎯 TDD Vibe`** прямо в панели ввода сообщений (рядом со слотом Plan Mode):
* Подсвечивается неоновым зеленым цветом при включении.
* При наведении показывает подсказку с 5 фазами процесса.
* При клике автоматически активирует команду `/vibe` в поле ввода.

## 📦 Установка

### Вариант A. Подключение локального чекаута
```bash
npx @deepseek-ai/dsh plugin --profile web add link:/path/to/dsh-vibecoding
```

### Вариант B. Установка напрямую из GitHub
```bash
npx @deepseek-ai/dsh plugin --profile web add github:denssdenss99-a11y/dsh-vibecoding
```

```bash
npx @deepseek-ai/dsh web
```

## 🛠️ Инструменты плагина для агента

Плагин регистрирует следующие инструменты в `ctx.tools`:

| Инструмент | Описание |
| :--- | :--- |
| `run_tdd_cycle` | Запускает тесты проекта (`npm test`, `pytest` и т.д.) и возвращает статус `RED` или `GREEN` со стектрейсом для авто-исправления. |
| `worktree_create` | Создает изолированный git worktree в `.worktrees/<name>` с новой веткой. |
| `worktree_list` | Показывает список всех активных изолированных воркдеревьев. |
| `worktree_remove` | Очищает worktree после успешного прогона и мерджа. |

## ⚙️ Настройка моделей (Оркестратор vs Воркеры)

В файле `~/.dsh/profiles/web/cordis.patch.yml`:

```yaml
# Оркестратор сессии (умная модель):
- id: agent-default-model
  name: "@deepseek-ai/dsh-agent-default-model"
  config:
    provider: gemini-oauth
    model: gemini-3.1-pro
    reasoningEffort: high

# Для воркеров (сабагентов subagent) агент автоматически задействует быстрые модели (gemini-3.8-flash)
```
