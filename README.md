**dsh-vibecoding** — плагин и TDD-оркестратор для [DeepSeek Harness (DSH)](https://github.com/deepseek-ai/deepseek-harness), превращающий обычный хаотичный «вайбкодинг» в строгий, надежный и предсказуемый инженерный процесс с контролем качества, изоляцией веток и защитой данных.

Включает удобную **кнопку переключения режима прямо в панели ввода DSH Web UI**!

---

## 🛑 Проблема «неправильного» вайбкодинга

1. **Промпт без деталей:** модель принимает архитектурные решения вслепую, додумывая бизнес-логику.
2. **Потеря контекста:** на длинных дистанциях диалога модель «забывает» исходную постановку задачи.
3. **Слепая вера в ответ:** фраза модели *«Готово, всё работает»* не означает, что код хотя бы запускается.
4. **Одноагентный режим:** одна дорогая модель делает и сложное планирование, и рутинный кодинг в один поток, быстро исчерпывая лимиты контекста.

---

## ⚡ 5 Элементов надежного AI-Workflow

1. ❓ **Опрос (Clarification Gate):** Запрет на написание кода до того, как модель задаст 1–3 уточняющих вопроса по граничным условиям и контрактам. Разблокируется через `complete_interview`.
2. 📄 **Спецификация (Anchor):** Автоматическая фиксация плана и контрактов в `docs/specs/<feature>.md`, удерживающая фокус контекста при любых длительных диалогах.
3. 🔴 **TDD-контракт (Red -> Green Loop):** Тесты пишутся **ДО** реализации. Инструмент `run_tdd_cycle` проверяет, что тест сначала упал (RED), затем воркер крутит цикл исправлений сам до тех пор, пока тест не станет зеленым (GREEN).
4. 🌿 **Изолированные ветки (Git Worktrees):** Инструмент `worktree_create` создает изолированную директорию `.worktrees/<task>`, защищая основную ветку от поломок и конфликтов.
5. 🤖 **Оркестрация (Оркестратор + Рой воркеров):** Ведущая модель проектирует и валидирует, а быстрые модели параллельно пишут код под падающие тесты в своих ветках, возвращая компактный JSON-отчет в основной контекст.

## 🖥️ UI Кнопка в DSH Web

Плагин регистрирует кнопку с иконкой волны **`⚡ Vibe Harvester`** в панели ввода сообщений (справа, рядом с кнопкой отправки):
* **Тихий режим:** переключает режим на лету через локальный API без вставки лишнего текста в поле ввода.
* **Подсветка:** светится градиентным неоновым цветом в активном состоянии.
* **Подсказка:** при наведении мыши или фокусе с клавиатуры отображает интерактивное окно с 5 фазами и текущим статусом.

## 🛠️ Инструменты плагина для агента

Плагин регистрирует 10 специализированных инструментов в `ctx.tools`:

| Инструмент | Описание |
| :--- | :--- |
| `complete_interview` | Разблокирует Фазы 2–5 (Gatekeeper) после фиксации требований с пользователем. |
| `create_worker_brief` | Генерирует супер-компактный lean-промпт для субагентов (экономия до 80% токенов в основном контексте). |
| `run_tdd_cycle` | Запускает тесты проекта (`npm test`, `pytest`, `cargo test`) и возвращает `RED` или `GREEN` со стектрейсом. |
| `worktree_create` | Создает изолированный git worktree в `.worktrees/<name>` с новой веткой (автоматически защищает `.gitignore` и фиксирует тесты). |
| `worktree_list` | Показывает список всех активных изолированных воркдеревьев. |
| `worktree_merge` | Сливает выполненную ветку воркера обратно в текущий `HEAD`. |
| `worktree_remove` | Безопасно очищает worktree после слияния (автоматически сохраняет незакоммиченный код воркера в ветку). |
| `verify_deliverable` | Автоматический смоук-тест: проверяет синтаксис JS/HTML без опасного исполнения (`vm.Script`), внешние зависимости и запуск в Headless Chrome. |
| `checkpoint_create` | Создает контрольную точку (git tag + git stash snapshot) перед слиянием или рефакторингом. |
| `checkpoint_restore` | Безопасный откат к контрольной точке (предварительно сохраняет незакоммиченные файлы в `git stash`). |

## 🛡️ Безопасность и Safe Mutate Guard

1. **Safe Mutate Guard:** запрещено молча удалять файлы, блоки или сущности. Любые деструктивные действия требуют предварительного подтверждения пользователя на русском языке.
2. **Защита данных при очистке:** `worktree_remove` и `checkpoint_restore` никогда не сносят несохраненный код — все промежуточные изменения автоматически фиксируются в ветках или `git stash`.
3. **Безопасная проверка синтаксиса:** встроенные скрипты HTML проверяются через AST-компилятор Node.js `vm.Script` без физического запуска кода в системе.
4. **Защита от выхода за пределы проекта:** вызовы инструментов ограничены корнем репозитория (`path traversal guard`).

## ⚙️ Настройка моделей (Оркестратор vs Воркеры)

В файле `~/.dsh/profiles/web/cordis.patch.yml`:

```yaml
# Оркестратор сессии (умная модель):
- id: agent-default-model
  name: "@deepseek-ai/dsh-agent-default-model"
  config:
    provider: gemini-oauth
    model: gemini-3.1-pro
    reasoningEffort: high

# Для воркеров (субагентов subagent) агент автоматически задействует быстрые модели (gemini-3.8-flash)
```
