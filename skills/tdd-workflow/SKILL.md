# ⚡ Автономный режим Vibe SOP (Software 3.0 OS)

При активации плагина или вызове `/vibe <task>` агент действует строго по законам Vibe SOP:
> *«Можно делегировать написание кода, но нельзя делегировать понимание»*

---

## 📜 12 ЗОЛОТЫХ ПРАВИЛ VIBE SOP

1. **Классификация поставки на шаге 0 (Delivery Archetype):**
   - **`[STANDALONE / DEMO / GAME / SANDBOX]`**: Интерактивные прототипы, игры, песочницы, инструменты, или требование «открыть сразу в браузере».
     - **Строгий запрет на бандлеры (Zero-Build Step):** Использовать модульный vanilla JS/ESM, CDN с fallback или локальные скрипты в `libs/`.
     - **Обязательное требование:** Должен открываться напрямую двойным кликом в Finder (`file://`) без белых экранов и без bare npm imports в HTML.
   - **`[FULLSTACK / PRODUCTION APP]`**: Долгосрочные сервисы, дашборды, бэкенды. Стандартный бандлер (Vite), `package.json`, декомпозиция.

2. **Сначала план, потом код (`scope.md`):**
   - Создай лаконичный чек-лист из 3–5 пунктов в `scope.md` через стандартный инструмент `write` до написания первого файла кода.
   - Отмечай выполненные пункты `[x]` по ходу реализации.

3. **Правило 90% уверенности:**
   - Если уверенность в архитектуре, схеме данных или контрактах ниже 90% — кодинг запрещен. Сформулируй 1–2 конкретных вопроса пользователю.

4. **Хирургический режим, Anti-Scope-Creep и оффлайн-проверка синтаксиса:**
   - **Защита от оверинжиниринга (Anti-Scope-Creep)**: При запросе на исправление ошибки данных, пропущенного ассета/картинки или вопроса «как починить/перегенерировать?» — реши проблему напрямую (CLI/скрипт/БД/API) за 4–8 шагов. НЕ пиши самовольно UI-кнопки и REST-эндпоинты; доложи о результате и спроси пользователя, нужна ли автоматизация в UI.
   - **Оффлайн-проверка синтаксиса**: Запрещена отладка через циклические рестарты демона сервера на живом порту (`start -> curl -> 500 -> kill -> restart`). Синтаксис и импорты проверяются локально за 1 шаг (`python3 -m py_compile`, `node --check`).
   - Действуй точечно: `grep -> срез 30-50 строк -> edit -> 1 тест -> git commit`. Лимит шагов на подзадачу — 10.

5. **Защита от сбоев ОС и окружения (OS Guardrails):**
   - **Защита от кириллицы/пробелов:** При создании `package.json` всегда указывай безопасный ASCII-slug (`"name": "app"` или `"sandbox"`), не копируя имя каталога.
   - **Защита кэша npm:** Используй флаг `--prefer-offline` или временный кэш `npm_config_cache=/tmp/npm-cache` для предотвращения `EPERM` блокировок.

6. **Git как точки сохранения (Save Points):**
   - После каждой работающей и протестированной фичи делай нативный коммит: `git commit -am "savepoint: [feature]"`.

7. **Жесткий откат при двух ошибках (2-Strike Rollback):**
   - Если команда сборки или тест упали 2 раза подряд — **ОСТАНОВИСЬ!**
   - Выполни откат: `git reset --hard HEAD` к последнему рабочему сейвпоинту.
   - Сформулируй 1 строку RCA (Root Cause Analysis) и смени архитектурный подход вместо нагромождения костылей.

8. **Инварианты предметной области (No Dead Code):**
   - Для физических движков (Matter.js, Cannon.js, Rapier): обязательная предзагрузка вспомогательных библиотек (например `poly-decomp`) до инстанцирования тел.
   - Web Audio: синтез звука инициализируется только по первому пользовательскому жесту (`pointerdown`/`click`).

9. **Многоуровневая верификация (`browser_smoke`):**
   - Чистая математика и логика: пиши юнит-тесты на нативном раннере `node --test` или Vitest.
   - Браузер и визуал: **ОБЯЗАТЕЛЬНО** вызови `browser_smoke({ url: "http://localhost:<port>" })` перед сдачей проекта. Проверь 0 ошибок консоли и 0 uncaught exceptions.

10. **Быстрый вход в существующий проект и точечное чтение:**
    - При открытии репозитория читай первым делом `.dsh/memory/memory.md` и `git log -n 3 --oneline`. Запрещено дампить полные файлы в контекст; читай срезами по 30–50 строк.
    - В конце сессии зафиксируй решения в `.dsh/memory/memory.md`.

11. **DSH Write Convention:**
    - При вызове инструмента `write` никогда не передавай аргумент `justification` без запроса прав через `sandbox_permissions`.

12. **Автономная сдача под ключ и гигиена контекста:**
    - Сохраняй код прямо на диск, проведи `browser_smoke`, выдавай `[🎯 MILESTONE SEALED]` с хэшем коммита.
    - При длинных сессиях (30+ шагов) или смене тем активно напоминай пользователю вызвать `/compact`, чтобы сбросить накопленный контекст и избежать взрывного роста токенов.

## 🧰 Доступные инструменты плагина (5 Sharp Tools)

1. **`browser_smoke`**: Нативный запуск Headless Chrome по CDP для мгновенной проверки веб-страницы на отсутствие `console.error` и JS-ошибок.
2. **`worktree_create`**: Создание изолированного Git-ворктри для параллельной работы субагентов.
3. **`worktree_merge`**: Атомарное слияние ветки ворктри в основную ветку.
4. **`worktree_list`**: Просмотр активных ворктри проекта.
5. **`worktree_remove`**: Безопасное удаление ворктри с сохранением незакоммиченных изменений в ветке.
