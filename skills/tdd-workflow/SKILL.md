# Режим надежной разработки (TDD + Parallel Multi-Agent Workflow)

Когда активирован этот режим или получен префикс `/vibe`:

## Фаза 1. Опрос (Clarification)
- **ЗАПРЕЩЕНО** писать код или редактировать файлы проекта на этом шаге.
- Задай пользователю 2–4 конкретных уточняющих вопроса через `ask_user_question`:
  - Граничные условия и поведение при сбоях.
  - Стек библиотек и форматы входных/выходных данных.
  - Критерии приемки (DoD).
- Дождись ответов пользователя перед переходом к Фазе 2.

## Фаза 2. Спецификация и Декомпозиция (Anchor & Split)
- Создай файл `docs/specs/<feature-name>.md`.
- **ОБЯЗАТЕЛЬНОЕ РАЗБИЕНИЕ:** Раздели задачу минимум на 2 независимые подзадачи:
  - Подзадача A (например: геометрия / структуры данных / бизнес-логика).
  - Подзадача B (например: рендеринг / шейдеры / UI-компоненты / middleware).
- Для каждой подзадачи зафиксируй интерфейсы и критерии приёмки.

## Фаза 3. Изоляция веток (Git Worktrees)
- Для КАЖДОЙ подзадачи создай изолированное рабочее дерево:
  - `worktree_create({ taskName: "<subtask-a>" })` → папка `.worktrees/<subtask-a>`
  - `worktree_create({ taskName: "<subtask-b>" })` → папка `.worktrees/<subtask-b>`
- Это защищает проект от конфликтов параллельной работы.

## Фаза 4. Параллельный запуск воркеров (Subagent Swarm)
- **ЗАПРЕЩЕНО делать реализацию последовательно в один поток самому!**
- Ты — Оркестратор. Вызови инструмент `subagent` ОДНОВРЕМЕННО для обеих подзадач в одном ответе (с параметром `run_in_background: true`):
  - Воркер 1: целевая директория `.worktrees/<subtask-a>`, контракт задачи A.
  - Воркер 2: целевая директория `.worktrees/<subtask-b>`, контракт задачи B.
- Каждому воркеру дай TDD-директиву: «Сначала напиши тест, убедись, что упал (RED), затем пиши код до зеленого теста (GREEN)».

## Фаза 5. Мердж и сведение (Integration & Green Release)
- Дождись завершения воркеров с зелеными тестами.
- Смерджи ветки в main (`git merge vibe/<subtask-a>`, `git merge vibe/<subtask-b>`).
- Удали временные воркдеревья через `worktree_remove`.
- Прогони общие тесты проекта через `run_tdd_cycle` и сдай результат пользователю.
