# Режим надежной разработки (TDD + Multi-Agent Workflow)

Когда активирован этот режим или получен префикс `/vibe`:

## Фаза 1. Опрос (Clarification)
- **ЗАПРЕЩЕНО** писать код или редактировать файлы проекта на этом шаге.
- Проанализируй задачу и задай пользователю 2–4 конкретных уточняющих вопроса:
  - Граничные условия и поведение при сбоях.
  - Стек библиотек и форматы входных/выходных данных.
  - Критерии приемки (DoD).
- Дождись ответов пользователя перед переходом к Фазе 2.

## Фаза 2. Спецификация и План (Anchor)
- Создай файл `docs/specs/<feature-name>.md`.
- Зафиксируй:
  1. Цель и критерии приёмки (Definition of Done).
  2. Архитектурные контракты (интерфейсы, схемы данных, сигнатуры).
  3. Чек-лист разбиения на изолированные подзадачи.
- Этот файл служит постоянным «якорем контекста».

## Фаза 3. TDD-Контракт (Red -> Green Loop)
- Для каждой подзадачи СНАЧАЛА напиши тест.
- Запусти тест через инструмент `run_tdd_cycle` или bash-команду (`npm test`, `pytest`, `cargo test`).
- **Контроль RED**: Убедись, что тест падает с понятной ошибкой (так как код ещё не написан).
- **Цикл реализации (GREEN)**:
  1. Напиши минимальный рабочий код.
  2. Запусти тесты снова.
  3. Если упало — прочитай вывод ошибки, исправь причину, повтори запуск.
  4. Завершай задачу ТОЛЬКО тогда, когда тесты стали зелеными.

## Фаза 4. Изоляция веток (Git Worktrees)
- Для параллельных подзадач используй инструмент `worktree_create`:
  `worktree_create({ taskName: "<name>" })`
- Вся работа ведется изолированно в `.worktrees/<name>`, не засоряя основную ветку.

## Фаза 5. Оркестрация (Subagents)
- Делегируй параллельные задачи под-агентам (`subagent`), передавая им:
  - Путь к `docs/specs/<feature-name>.md`
  - Путь к изолированному worktree
  - Спецификацию тестов
- После завершения работы под-агентов проверь общий регрессионный тест, смерджи ветку и удали worktree через `worktree_remove`.
