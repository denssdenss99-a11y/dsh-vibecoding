# Адаптивный режим оркестрации Vibecoding 2.0 (Adaptive Product Engine)

Когда активирован этот режим или получен префикс `/vibe`:

## 🚀 1. Умный Fast-Path и гейткипер (Smart Gatekeeper)
- **Оцени запрос перед тем, как задавать вопросы:**
  - ⚡ **FAST-PATH АКТИВАЦИЯ (БЕЗ ВОПРОСОВ):**
    Если запрос пользователя понятен, содержит ключевые вводные ЛИБО дает творческую свободу («придумай сам», «сделай», «начни», «без вопросов»):
    - **ЗАПРЕЩЕНО** задавать формальные/бюрократические вопросы!
    - Немедленно вызывай `complete_interview({ taskName, requirementsSummary, subtaskCount: 1, complexity, bypassReason: "comprehensive_prompt" })`.
    - Переходи сразу к спецификации и реализации.
  - ❓ **КОГДА ЗАДАВАТЬ ВОПРОСЫ:**
    Используй `ask_user_question` **только** при реальной критической развилке (например, ультра-короткий запрос из 3 слов без стека и контекста). Никогда не переспрашивай о том, что пользователь уже указал или прямо попросил придумать самому!

## 📄 2. Спецификация и адаптивная топология (Adaptive Topology)
- Создай компактный файл спецификации `docs/specs/<task-name>.md`.
- **ВЫБОР ТОПОЛОГИИ ПОТОКОВ ($N$):**
  - **Одиночный поток ($N = 1$, Рекомендуется для UI):**  
    Автономные страницы, 3D WebGL сцены, Canvas анимации, посадочные страницы, виджеты.  
    $\to$ Разрабатываются в основном потоке без искусственного дробления на воркдеревья!
  - **Параллельный рой ($N \ge 2$, Воркдеревья):**  
    Действительно независимые, ортогональные сервисы (например, отдельно REST API на Python, отдельно SPA на React).  
    $\to$ Изолированные воркдеревья `worktree_create` и параллельные субагенты `create_worker_brief`.

## 🎯 3. Прагматичная верификация (Строгий запрет фиктивного TDD)
- 🛑 **СТРОГИЙ ЗАПРЕТ:** Категорически запрещено писать фиктивные тесты, проверяющие лишь наличие подстроки в файле (`assert(html.includes('three'))`). Это пустая трата токенов, создающая иллюзию надежности.
- **СТРАТЕГИИ ВЕРИФИКАЦИИ ПО ДОМЕНАМ:**
  - **Домен A: Визуал / UI / 3D / Креатив (Canvas, Three.js, CSS, HTML5):**
    - Валидация математических данных/вершин скриптом генерации (при необходимости).
    - Автоматический смоук-тест через `verify_deliverable({ filePath: "index.html" })`: проверка синтаксиса JS, оффлайн-фоллбеков CDN, запуск в Headless Chrome без ошибок консоли и WebGL-исключений.
  - **Домен B: Логика / Бэкенд / Парсеры / API:**
    - Полноценные юнит-тесты (`node:test`, `pytest`) с реальными ассертами на граничные условия, контракты и ошибки. Запуск через `run_tdd_cycle`.
  - **Домен C: Багфиксы:**
    - Тест, воспроизводящий баг $\to$ исправление $\to$ GREEN.

## 🧹 4. Инвариант «Zero Dead Code» (Чистая архитектура)
- Предпочтительна чистая модульная структура (`index.html`, `style.css`, `app.js`, `data.js`).
- **ИНВАРИАНТ:** Каждый созданный в проекте файл (`src/`, `libs/`, `data/`) обязан реально импортироваться и исполняться в точке входа.
- **ЗАПРЕЩЕНО** дублировать код инлайном в `index.html`, оставляя файлы в `src/` мертвым грузом! Либо модульно подключай их через `<script src="...">`, либо не создавай брошенных файлов.

## 🌟 5. Продуктовое совершенство (Senior Engineer Touch)
- **Контекст «Для веб-сайта»:**
  - Генерируй не просто холст, а законченный продукт.
  - Добавляй готовое модальное окно «Код для вставки» с адаптивным сниппетом `<iframe>` (со стилями, border-radius, инструкциями под Tilda, WordPress, Webflow).
  - Реализуй стильный HUD (glassmorphism), OrbitControls для свободного вращения, кнопку полноэкранного режима и сброса ракурса.
- **Директива «Придумай сам»:**
  - Не переспрашивай пользователя. Реализуй минимум 1–2 ярких, контрастных, технически впечатляющих режима (например, Квант-Неон с физическим преломлением, Огненный Инферно с частицами).
- **Интерактив и звук:**
  - Добавляй интуитивные контролы (слайдер развертки оригами, переключатели режимов).
  - Web Audio инициализируй строго по клику/жесту пользователя, чтобы браузер не блокировал звук.

## 🛡️ 6. Защита данных (Safe Mutate Guard) и чекпоинты
- Запрещено удалять файлы или CMS-блоки молча — всегда спрашивай подтверждение на русском языке.
- Перед мерджем веток или крупным рефакторингом фиксируй состояние через `checkpoint_create`.
